# 急救制作数据与运行时接入修复

急救原来只有 16 段固定攻略和全程购物清单，没有 `ProfRecipes` 行或 `rinfo`；学习流水线和运行时还单独排除了急救。此次补齐三语言的 32 条制作配方，保留原 16 段攻略、制作次数、全程购物数量，以及原生 TOC、惰性加载和存档入口。总览配方数量同步为 32。

## 数据来源与核对

- 制作材料、产物、产量和技能归属使用已经封存且逐文件 SHA-256 校验的 Wago `wowf` **1.60.1.70685** 原始 DB2。没有从旧候选表或其他专业的相似配方复制数值。
- 2026-10-30 另行采回 32 个技能页、17 个教材页和2个 NPC 页，共51页，使用 Wowhead 的 Forever 分区。50页 HTTP 200，教材23689为404；技能470349虽为200，但页面没有对应配方记录，保留解析缺口。网页标示补丁1.60.1，不声称网页每个字段都绑定精确DB2 build。
- 32条制作配方均有材料和产物数据。31条有网页配方记录，其中30条有颜色节点，可与DB2节点交叉核对。30021和470349保留DB2制作事实，不据网页缺失推断可学习或已删除。
- 黄、灰节点取 `SkillLineAbility`，绿节点按既有规则 `floor((yellow + grey) / 2)`，并与有值的网页节点核对。网页橙色为0不解释为技能0；没有真实学习门槛时仅保留黄线参考，未学配方仍受学习来源校验。
- 亚麻绷带3275为**每次1个**：DB2和网页配方记录均为1，用户于本次对话游戏内确认1。网页技能提示中的2与上述证据冲突，不采用该提示值。简易药膏1259342每次3个。
- 教材门槛与变黄节点分开。例如急救强效治疗药水1244434的教材255723要求155，变黄175；不再把网页显示的黄线叠加成175的学习条件。

逐条制作事实及输入哈希见[制作数据审计](../data_pipeline/professions/reports/first-aid-recipes-2026-10-30.json)。网站交叉核对入口：[亚麻绷带](https://www.wowhead.com/forever/spell=3275/linen-bandage)、[简易药膏](https://www.wowhead.com/forever/spell=1259342)、[强效治疗药水教材](https://www.wowhead.com/forever/item=255723)。

## 完成的功能

- 配方页显示真实的产物、单次材料、材料成本和技能节点；三语言使用同一组事实。
- 固定路线按逐配方材料汇总，完整路线仍与原14种材料购物清单一致；部分目标也能计算实际用料，不再只能显示全程参考清单。
- 已学配方可正常参与路线和执行。打开急救面板或训练师窗口后，客户端观察现在有原生配方种子可匹配。
- 急救使用统一学习、教材采购、执行及HUD校验。按用户后续要求，未知学习来源默认按训练师处理；明确的教材、任务等来源继续保留。价格和拍卖库存仍独立检查。
- 学习指纹更新使旧路线需要重算，执行历史保留。急救仍使用原固定攻略模式，没有新增自动后台搜索。

学习资料包含34个技能引用，其中32个是制作配方，另2个是专业等级学习引用。发布仅替换急救记录：共享工作区中其他专业的全部既有学习事实经过解码比较后原样保留。完整新生成器中尚未发布的其他专业字段不随此次补数带入。详见[定向发布审计](../data_pipeline/professions/reports/first-aid-publication-2026-10-30.json)。

## 未知来源的默认规则

用户明确指定“急救未知来源就默认为训练师”。运行时对没有已知学习渠道、也没有教材ID的急救配方补上训练师默认路径，覆盖以下三条：

| 技能 | 配方 | 当前行为 |
| --- | --- | --- |
|10841|厚魔纹绷带|未知来源默认训练师|
|18629|符文布绷带|未知来源默认训练师|
|18630|厚符文布绷带|未知来源默认训练师|

这是用户指定的运行规则，原始采集记录仍保留未知状态。默认路径标有`defaultTrainer=true`，不填写未经确认的NPC或学习费用；界面显示训练师，路线和执行采用同一规则。已知技能门槛、角色条件和客户端不可用状态仍生效。明确的教材、任务、训练师等渠道不因获取详情缺失而被替换；其他专业不套用此默认规则。学习指纹已更新，旧路线需重新计算。

## 重现

制作数据生成入口：

```powershell
python -m data_pipeline.professions.first_aid --raw RAW_DIR --root . --audit data_pipeline/professions/reports/first-aid-recipes-2026-10-30.json
python -m data_pipeline.professions build --raw RAW_DIR --output GENERATED.lua --report LEARNING_REPORT.json
python -m data_pipeline.professions.publish_profession --target Core/Data/Data_ProfLearningSources.lua --generated GENERATED.lua --profession first-aid --report PUBLICATION_REPORT.json
```

最后一步是定向发布器，不是采集器：急救全部记录只取本次来源生成物，其他专业原样保留，不以旧文件补缺急救。该命令需要测试依赖中的Lua5.1运行时。不同build、空专业或发布期间目标变化会拒绝写入。

本次源数据与详细机器记录位于[任务证据目录](../.pipeline-runtime/first-aid-complete-20261030/)。离线测试模拟价格和角色状态；不将它们表述为真实游戏报价或操作验收。更新插件后需要 `/reload`，打开急救面板并重新计算路线。
