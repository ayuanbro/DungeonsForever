## 公共逻辑与数据限制

固定攻略和自动规划使用同一组动态配方服务，检查 dev 资料及客户端已经提供的条件；旧阻止标记会重新计算。已明确不可用的配方不能继续作为可执行步骤，角色条件改善后也不应永久保留旧阻止结果。固定攻略的技能区间、次数或购物清单本身不构成制作配方。

静态冲突采用 dev 优先：`rows > ProfLeveling.rinfo > crafted/enchants`；明确客户端观察优先于静态参考。材料、产量、冷却和学习要求分开确认，不能由已学事实推导历史学习等级，也不能由一次零剩余冷却推断不存在共享冷却。

通用学习判断可处理显式输入的多条件、替代路线、任务、种族／职业 mask 和未知状态；当前没有加载 modularization 的逐配方条件投影。因此它不会自动知道所有参考附加限制。`E.Capture` 将覆盖完整性保留为未确认，不以全局未知状态替代逐配方事实，也没有硬编码缺失条件清单。

晋级完成必须由角色真实专业上限或客户端 API 证明，不能用搜索中的假设上限充当证据。采集导航、手动精华转换、晋级提示和专精任务不伪造成制作升点或免费材料。
