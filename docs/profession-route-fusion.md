## 加载和保存结构

- 仍由主 `DungeonsForever.toc` 加载 `Core` 文件，保留 `LoadOnDemand: 0`、原有页面与 HUD 入口。没有引入独立专业插件、ModuleAPI、目录服务或全局追踪门禁。
- 保存变量仍只有 `DungeonsForeverDB`。原有设置及 `prof.track` 继续使用；旧版执行记录转换时保留 `legacyTrack` 原始步骤、进度和产出备份。
- 新增 `prof.economy[角色]` 存放客户端观察，`prof.routePlans.characters[角色]` 保存路线候选，每个专业最多保留四个候选。执行计划自行保存完整快照，候选淘汰不会删除执行记录。
- 无法识别的路线缓存保持原样，返回需要重新计算的诊断，不用空表覆盖。
- `Core/Data` 的原文件、结构、TOC 顺序和语言条件保持原样，不新增数据文件，也不通过运行时补充层改写静态表。参考分支缺少的必要资料仅列入文档。没有提高插件版本号。

## 融合后的行为

| 环节 | 实现及行为 |
| --- | --- |
| 路线入口 | `Core/ProfRoutePlans.lua` 为页面、HUD 和精算提供统一门面。“最省钱”默认后台求解；其他方案遇到工具、专精任务或精华转换依赖时，共用求解器并保留原方案评分。 |
| 输入校正 | `Core/ProfSolverCapture.lua` 和 `Core/ProfClientScan.lua` 使用现代或经典客户端实际读取的材料、最低产量、学习门槛和可用性，仅校正本来存在的配方。`Core/ProfLearning.lua` 保留通用条件判断算法，只能处理已有或显式输入的条件；参考分支的新增静态条件未导入。静态配方保持 `rows > rinfo > crafted/enchants`，客户端正面观察优先。未打开的专业面板、仅已学列表或失败的读取不作为配方不存在的证据。 |
| 搜索 | `Core/ProfRouteSolver.lua` 同时比较整数采购批量、直接购买、递归制材、图纸来源、有限拍卖数量和产物复用。默认 CPU 预算 5000 毫秒，精算 8000 毫秒；单次调度约 2 毫秒，默认搜索前沿上限 20000。CPU 预算不是用户等待的墙钟时间。 |
| 最优性 | 区分已知输入模型最优、配方覆盖完整、报价完整、搜索范围受限及预算截止。达到目标或找到可行路线不代表全局最优。 |
| 缓存和重算 | 技能、报价或客户端资料变化标记旧路线过期，查看页面或 HUD 不会因此自动更换执行计划。“重新计算”才应用新的输入；取消、继续和结束会隔离旧调度回调。 |
| 执行账本 | `Core/ProfExecution.lua` 保存冻结步骤、制作事实、确认产出、材料用途和消费顺序；`ProfTrack` 保留兼容接口，制作事件由执行账本统一观察。技能到达终点但后续材料尚未满足时，步骤继续保留。 |
| 续算与补料 | 只继承已确认、扣除实际消耗后仍在背包中的路线自产材料。原有背包库存和未确认产出不自动当作免费库存；不足部分通过采购或递归制材补足。 |
| 精华转换 | `Core/ProfEssences.lua` 支持五组已确认的经典大小精华关系，1 大对应 3 小。转换作为手动操作，不产生专业升点，也不当作配方制作次数；HUD 要求明确确认。 |
| 回血 | 使用冻结售价，保留中间产物的成本归属，避免重复计入出售收入。采用拍卖收入需要已知卖店价、净价高出卖店价超过 100 铜，以及两天内、至少 40 件、完整且排除自售的可靠数量观察；采用后按剩余成品全部售出估算。手续费未知保持未知。 |
| 晋级提示 | `Core/ProfRanks.lua` 读取 dev 原有晋级资料和角色实际技能上限，页面及 HUD 提供训练、教材或任务参考。提示不修改冻结步骤；不能用求解器模拟的上限证明角色已经晋级。 |
| 特殊路线 | `Core/ProfFishing.lua` 独立处理纯钓鱼烹饪的筛选、商人组价、图纸和产量；`Core/ProfGathering.lua` 提供不生成材料的采集导航。制毒的页面和 HUD 均保持固定模式。 |

dev 的急救自动规划入口和采矿熔炼不启用自动规划的策略保持不变。原 dev 急救只有固定攻略，缺少相应配方材料、产物及产量等元数据；当前仍明确返回不可行，固定攻略可以查看，不能把缺失材料当作零成本路线。14 个固定配方的参考证据与必要字段已单列在[dev 数据缺口](profession-dev-data-gaps.md)，没有接入运行时。

## 游戏内验收

1. `/reload` 后打开专业升级页，启用自动路线，检查购物清单、技能目标、专精和工具步骤。
2. 开始追踪，先完成部分制作；确认技能提前达到目标时，后续仍需使用的材料步骤不会被跳过。
3. 修改价格或排除设置，确认执行计划保持原样并提示重算；重新计算后核对自产材料的剩余数量。
4. 附魔路线实际进行大小精华转换，在 HUD 确认转换数量，核对后续材料需求。
5. 制作次数超过预计值后计算补料，再测试关闭界面、重新登录及晚到制作产出；验证晋级提示随实际技能上限更新。
