# 急救配方参考页与升级价格提示修复

> 历史阶段记录：随后按用户要求补齐了急救制作数据和学习资料接入，当前状态见[急救数据修复](first-aid-data-20261030.md)。本文的“配方行为 0”“仅参考页”等描述只代表补数前的状态；缺表时的安全降级仍保留。

现有Data可以生成急救配方参考目录，不能单凭这些资料生成完整、可计算逐配方成本并执行的配方表。本次补上了参考页入口及显示，修正升级页把配方资料缺失误报成拍卖行缺价的问题；没有启动采集或修改任何Core/Data文件。

## 现有数据能提供什么

| 现有资料 | 数量 | 本次用途 |
| --- | ---: | --- |
| 固定升级攻略 | 16段、14个不同技能ID | 生成可查阅的配方引用，显示攻略使用区间 |
| 1–300全程购物清单 | 14种材料 | 按当前真实采购报价显示材料参考价 |
| 学习技能引用 | 31个ID | 作为核对清单，不能全部视为制作配方 |
| 原生急救配方行及rinfo | 均为0 | 缺少完整配方的直接输入 |

攻略涉及的14个技能为：3275、3276、3277、3278、7928、7929、10840、10841、18629、18630、1244431、1244432、1244433、1259342。

仍缺少每条配方的产物ID/产量、单次制作材料、黄绿灰节点及明确学习来源/条件。攻略使用区间不是配方的实际学习门槛；全程购物总量也不能反推每条配方的材料。因此参考页没有编造产物、材料、颜色节点或0铜制作成本。

其余17个学习引用未提升为完整配方：7934、7935、23787、30021、1230117、1244434、1244435、1244436、1259341、1259343、1259344、1259345、1259347、1259348、1259349、1262996、1263001。其中30021还出现在原资料的quest引用中，不能凭同一数值推断它的实体类型或制作关系。总览的`recipes=11`是既有概要字段，也不能替代逐条配方表。

## 修复后的界面

- 急救的“配方”标签原来因没有`ProfRecipes`行而隐藏，现在根据现有攻略开放参考页。14条引用去重显示，合并重复攻略段，可搜索名称或技能ID，名称和图标使用既有客户端查询；已学状态独立显示。
- 参考目录标明“逐配方资料待补全”。16段升级步骤的成本和来源也显示资料缺失，缺失原因不再误标为专精限制或单纯缺价。
- 全程购物清单已有报价时，升级费用卡和购物页显示“材料参考价”；它只包含现有清单的材料，不冒充含图纸和学习费的完整路线总价。
- 少量材料缺价时保留已知金额并显示下限；完全无报价时显示材料价格待补全。不会把未知价格显示成免费。
- 目标低于300时，不把全程材料清单按比例拼成目标所需材料；界面显示配方资料缺失，不显示“没有需要准备的材料”或0成本。
- 启用拍卖数量检查时仍核对库存，数量未知或不足会保留提示。商人采购仍要求既有可信供应商报价，不根据`sold`列表猜测免费或保证可得的库存。

后端仍保留`clientPending`、`feasible=false`及`completeCost=false`。新字段仅区分参考资料与材料报价，不能据此开始制作追踪或进入自动求解。第一阶段仍不接受无原生配方种子的急救客户端观察来补写目录，打开专业窗口不保证这些静态缺口自动补齐。

## 原因与兼容边界

急救原始资料没有逐配方信息，固定攻略汇总正确标记为未完成；旧界面却把`priced=false`统一解释成没有拍卖行信息。另外，`AuctionatorStatusText`在价格状态为正常时也落入了缺价提示。现在分别处理参考目录、材料报价和可执行性，并补上正常价格状态文字。

本次急救修复没有写入Core/Data。原有129个Data文件及TOC逐字节哈希与快照一致，既有加载顺序、语言条件、`ns.Init`及存档入口不变，没有新增模块或后台任务。独立的学习补充文件在同期其他工作中有更新，已保留并在机器记录中单列，不能把它算成本次急救改动。

## 离线验证

- 急救界面与原数据边界15项检查通过，覆盖标签入口、三语言参考行、搜索、费用卡、购物页、缺价、部分目标及数量不足。前一轮143项学习流水线/路径/UI检查通过；随后新增用例后的145项运行出现一次Windows临时清单替换拒绝访问，该失败单例独立重跑通过。
- 一轮专业全量检查404项时，403项通过、1项失败：`test_prof_formula_purchase_20261030`要求炼金技能17580的学习资料缺口列表为空。用本次急救修改前完整源码快照运行同一新增用例，仍在同一断言失败。同期独立补充资料更新后，该单例复验通过。该采购逻辑与用例属于其他工作，本次保留其改动；这些全量结果对应各次记录时点，不冒充最新整个工作区的统一验收。
- 相对本次修复前的完整选定TOC，当前工作区三语言冷启动内存差值最高约9.41 KiB；强引用参考行约11.20 KiB。同期还出现了学习判断、采购提示等其他改动，因此这个差值不单独归因于急救UI，也不是此前学习流水线的累计内存指标。
- 同机各300次有限离线采样：固定攻略汇总p95约1.46ms，参考行构建p95约0.26ms。配对的旧版固定攻略p95约1.96ms；共享主机有调度噪声，不据此宣称普遍提速或真实游戏中的硬耗时上限。线程CPU时钟观测过于离散，未用于验收。采样发生在同期学习补充文件更新之前，数据只代表记录时点。
- 验证使用模拟的明确材料报价，测试价格不是实时市场价格。真实客户端中的布局、市场报价和操作仍需更新插件后`/reload`验收。
