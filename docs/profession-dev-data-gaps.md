# dev 专业数据缺口

本清单说明：在保留 dev 原始 Data 文件、表结构和数量的前提下，哪些 modularization 参考资料没有接入，以及它们会影响什么。下列记录均是文档参考，不会经 TOC 加载、追加候选或改写原表。

比较基线为 dev `942a0ca1ae6478dabad4b0885f7abf4011338cc2`（原资料标记 `1.60.1.70338`），参考为 modularization `ec184e0d83f9d027e518b95eb0b2545699c5aeea`（目录及来源快照标记 `1.60.1.70532`）。源码解码、DB2 和网页快照有据，不等于当前客户端确认。

完整字段、来源路径、版本、SHA256、冲突双方和未知原因保存在[配方参考差异 JSON](profession-data-reference-differences.json)、[学习条件缺口 JSON](profession-learning-condition-gaps.json)及三份[原始证据清单](../validation/data)。文档导出字段 `candidateFields` 对应原证据中的 `acceptedFields`，元数据为 `appliedToRuntime=false`，不表示运行时采用。这里列出影响与优先级，不以条目数量证明功能等价。

配方与学习路线来自固定提交的 `AddOns/DungeonsForever_RecipeData/Data/Data_ProfCatalog.lua`，按其 `Framework/CatalogCodec.lua` 解码；材料、产物和阈值的原始核对资料包括 `SpellReagents`、`SpellEffect`、`SkillLineAbility` 等 DB2 快照及网页配方记录。来源时间、原始行和 SHA256 以 JSON 为准，不把网页标记版本当作当前角色观测。

## 如何区分必要资料和可选覆盖

要把某个技能当作可求解、可采购、可执行的制作步骤，至少需要可靠的技能身份、专业归属、材料及数量、产物语义、每次产量、学习／升点阈值，并处理已知的工具、专精、学习资格和冷却。无物品产出的附魔需要明确的无物品语义，不能误当缺失产物或创造一件成品。

图纸和获取来源对“允许规划尚未学会的配方”尤其必要，会影响资格及一次性费用；只规划已学配方时，它们未必改变制作材料。新增完整配方通常用于扩大候选覆盖，不是保留 dev 原有路线入口的前提，但缺少它们就不能声称覆盖与参考分支相同。

材料、产量或阈值缺失不能补成零、1 件或插值；不同来源冲突继续保留 dev，等待明确观察。专业晋级技能、任务能力和只有端点的记录，不因出现在专业目录中就成为零材料制作配方。高于 300 的参考学习门槛也不能钳低或反过来证明角色拥有更高上限。

## 学习条件投影缺失

通用算法能够判断显式提供的种族／职业 mask、等级、专业技能、前置能力、任务、教学物品条件，以及多条可替代获取路线。**modularization 的逐配方学习条件投影没有加载**，原 dev Data 没有的条件不会自动出现。这是数据覆盖缺口，不能把算法存在写成这些配方已经受完整约束。

具体例：

- 裁缝 1229504 的参考种族 mask 为 `8589934770`：种族 ID 1 被排除；种族 ID 2 通过这一位检查，也不证明其他未解读条件已经满足。
- 裁缝 1263425 有原文 `18446744072387644493` 的获取 mask，不能转成不精确浮点数或猜成无限制。
- 工程 8895 的参考学习路线含技能 225 等条件；只模拟地精能力 20222 不能证明完整参考资格满足。当前 dev 未加载这些附加条件，不能宣称技能 130 必然被这条参考规则阻止。
- 锻造和制皮原 dev 明确的专精要求继续有效；其他参考教学路线的多条件、任务和替代来源未接入。空条件列表或 `confirmed` 来源标签不自动证明条件完整。

完整缺口见[学习条件参考 JSON](profession-learning-condition-gaps.json)。这些缺失没有被硬编码为每配方未知标记；当前 capture 统一保留覆盖未确认。已学正面证据和客户端明确学习观察仍须按其实际语义处理。

## 理解与露营

理解的 dev 内容包含 `spell=0` 占位，没有可靠的制作技能身份可以与参考逐项对应；真实获取条件、升级路线和技能上限未建立。露营在固定参考提交中没有明确的模块配方归属，营地说明和其他专业关联的营地制作能力不能自动组成“露营升级路线”。

两项均保留原内容入口，不新增算法、伪造技能上限或以零材料配方补占位。需要真实技能身份及客户端行为后才能确定是否存在可规划模型。

## 后续确认顺序

1. 先确认实际使用路线必需的材料、产物、产量和阈值；急救固定步骤是直接阻塞项。
2. 对计划允许的未学配方确认图纸／训练师／任务和角色资格，核对 dev 与参考冲突，补充明确的冷却观察。
3. 在已确认基本数据后再考虑新增候选扩大覆盖；保留独立来源、版本与未知项。
4. 采集先建立节点与分段的可靠对应；理解与露营先确认技能身份和模型。

本轮只形成可审阅资料，不执行这些 Data 变更。离线算法、源码参考和客户端实测结论必须分别记录。
