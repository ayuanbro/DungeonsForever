# Wowhead 采集恢复与声望字段修正

本次修复采集器会话不一致的问题，并纠正一处声望等级转换错误。已经完成无 GUI Linux 的有限真实采集；尚未重新采集全部历史缺口，不把少量成功样本当作全量稳定性证明。

## 已修复

1. 旧实现硬写 Chrome 146 的 UA，而锁定依赖中的 HTTP 配置实际为 Chrome 152，无头 Chromium 为 156。新实现让普通 HTTP 使用其配套默认请求头；遇到 JavaScript 校验后，使用同一个原生 Chromium 会话继续取页面，不再将浏览器请求交给 curl，也不把 Cookie 转交给另一套网络栈。
2. 浏览器由一个专属线程持有和复用，两个 HTTP worker 可以排队调用；创建、请求及关闭均在所属线程完成。UA 从实际浏览器版本派生。本次浏览器一致性验证限定于 Linux。
3. 读取最终主文档的响应正文，不从正在跳转的 DOM 截取页面；读取正文期间发生新导航时重新等待。交互验证码不自动处理，普通 403 不冒充 JavaScript 校验。
4. 实际 HTTP 拒绝、连接异常、未发送请求分别记录为 `sourceBlocked`、`sourceError`、`notFetched`。熔断未请求带有 `attempted=false` 与 `errorCode=hostCircuitOpen`。恢复时保留以前的真实 HTTP 证据；未发送的重试单列为 `lastAttempt`。网页响应按内容哈希存放，避免覆盖尚未写入检查点的旧响应。
5. 生成规则升级为 **2**：DB2 `MinReputation` 的 0..7 转为客户端 `reaction` 的 1..8；缺失、空值、非法或越界保持未知。规则 1 的 183 条教材声望条件低了一档，涉及 178 个参考法术；现有原生目录涉及其中 180 条路径、175 个法术。已学配方、原始 Data 数值及实际制作要求不受此次修正影响。

声望例子：教材 `19447` 教技能 `23802`，要求银色黎明崇敬。DB2 原始值为 6，客户端比较值应为 7。新增回归确认：持有教材、角色声望为客户端 6（尊敬）时拒绝，7（崇敬）时通过；已学配方继续豁免历史学习限制。这是编号转换修正，不是覆盖 dev 的业务数值。

## 真实采集结果

所有采集均在无 DISPLAY/WAYLAND 的 Ubuntu 中运行，Wago 开始及结束仍为 `wowf 1.60.1.70658`。

| 检查 | 结果 |
|---|---|
| 从 latest API 重新下载 22 张 DB2 | 全部成功；与同版本原始包的 22 份 CSV 哈希一致 |
| 从新下载 DB2 发现候选，探测 12 个网页 | 12 个 HTTP 200，全部正确解析 |
| 在便携原始包的副本上恢复 16 个失败实体 | 12 个恢复并正确解析，4 个 HTTP 200 但缺少预期配方字段 |
| 定向检查技能 2671、2329 与教材 19447 | 三个均 HTTP 200 且实体匹配 |
| 定向检查教材 5577 | 正式页面真实 404；不是本次访问被拦截 |
| 真实浏览器组件冷启动及会话复用 | 2671、19447 均 200，随后正常关闭 |

恢复中未解析的四页为 `2577/2578/2579`（Mining）及 `3413`（Cooking），页面没有解析器需要的制作配方记录。它们继续保留为缺口，HTTP 200 本身不构成学习路径确认。

`5577` 在 Wago `Item` 表中存在，但 `ItemSparse` 没有详情；Wowhead 的正式页与公开工具提示接口均返回 404。因此 `5577 → 2671` 仍不能补成确认路径，也不能据此断言游戏内删除。不会从旧 Classic 数据或其他版本硬填。

公开工具提示接口已经验证可以取得部分资料：`19447` 返回专业、声望和教学技能信息，`2671` 返回技能提示。它没有提供完整训练师、商人、任务来源列表，也没有在本次新增为自动生成输入。后续可以为明确字段增加独立适配；完整来源仍需继续获取正式实体页面或取得同产品的授权数据。

## 交付与边界

更新后的补充 Data 来自恢复后的同版本原始包，包含 2,540 个参考技能、1,864 条确认学习路径，2,455 个技能仍有部分缺口。确认学习路径不等于已确认教材获取、价格或当前角色资格。完整逐项报告见交付目录 `dist/prof-learning/1.60.1.70658-rules2/report.json`。

生成后独立对比发现 36 条本专业学习技能门槛差异，全部继续保留 dev。逐条见 [native-conflicts-2026-10-29.json](native-conflicts-2026-10-29.json)；该对比结果不参与采集或生成。

历史原始包和 10 月 28 日验收记录保持原样；新的包与清单单独交付。历史记录中的受阻统计仍包含当时的熔断跳过，不能解释为本次又发送了数千次请求。

本次没有修改原始 129 个 Data 文件、加载架构或急救内容。补充资料指纹变化后，既有冻结计划保留历史与进度并提示重新计算。

完整的离线检查结果及原始证据哈希在 `recovery-acceptance-2026-10-29.json`。游戏内学习、采购与可见界面尚未验收。Docker 镜像未实际构建，本次 Linux 实测来自无图形 Ubuntu 环境。

Windows 当前工作区、只叠加本次修复的隔离提交版运行时，以及无 GUI Linux，分别通过 68 项测试。Linux 从新原始包断网重建的 Lua 与报告和 Windows 生成结果一致。完整专业 TOC 的离线内存复测最大为冷启动 252.64 KiB、单专业 501.18 KiB、全部专业 1311.80 KiB；指定 Capture 场景的交错采样 p95 回退 3.17%，低于 10% 门槛。这些结果不代表实际游戏界面或所有后台回调的硬耗时保证。
