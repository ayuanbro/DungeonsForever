⬆ 可交互：点左侧分类切换高亮 / 点品质筛选chip开关 / 点星星收藏。列表上方是筛选条：「稀有程度」= 品质多选（传说/史诗/精良/优秀/普通/粗糙，颜色按暴雪品质色）；「属性」下拉按词条过滤（主属性/耐力/命中/暴击…）。行 hover 星标复用心愿单方案（空心☆→金色★），右列来源格式 = boss 名 · 副本名，与掉落页同口径；「新增」小标标记无限服新加的装备。分页器：页脚上一页/下一页 + 页码 pills + 「共 N 件」计数。

分页的性能账：现有掉落页几百行不卡靠的是行池 + 视口剔除，但 1200 行的首次建帧与筛选/排序重排仍是全量开销；分页把帧数钉死在每页 50，行池大小 = 页容量，翻页只重填不建删（零 GC），GetItemInfo 每页只请求 50 条（数据未缓存时不会触发千次补发风暴）。筛选/排序/搜索变化一律跳回第 1 页，防落空页；当前页号记忆进 DungeonsForeverDB.gearFilter。

⑤ 坑位预防（动工前对照）

  • SwitchSub 总分发漏支 = 整页空白（10-11 实锤）——defs、TabsFor、内部分发、PD.Render 四处齐改，harness 静态断言同步更新。
  • 行池卫生——WipeRow 必清 r.dv；FillBonusTable 尾行兜底隐藏；行池大小 = 分页页容量，翻页只重填不建删；50 行内仍保留行级视口剔除兜底（窗口缩小/改尺寸时不裸奔）。
  • UI_RULES.md 先读——L 色阶真值表 / 间距 20-8-行距4 / 卡中卡提亮 / 圆角 HuiCardFX，动工按正式版规则，改规则须用户拍板。
  • 数据只存 ID——armor/req/ilvl 客户端可得的字段宁可运行期取，生成期少落；三语覆盖层整表替换，新增顶层段必须重跑两个数据生成器。
