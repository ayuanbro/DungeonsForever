⭐ 心愿清单（Wishlist）功能方案

DungeonsForever 1.7.x · 参考 Lootified 心愿单模式 · 仅方案稿，未写任何代码

① 功能总览：一条链路

玩家在副本掉落页随手收藏装备 → 心愿单按「来源」自动分组陈列 → 侧栏给出「去哪打」计划（打哪个本、杀哪个 boss）→ 拾取到心愿装备时屏幕提醒（二期）。全程只存 itemID，名字运行期向客户端要。

② 收藏按钮怎么加（掉落页行内星标）

借鉴 Lootified 的做法：星标是每个装备行右侧的独立按钮，平时隐藏，鼠标悬停该行时淡入；已收藏的行星标常亮金色（空心☆ = 未收藏，实心★ = 已收藏）。点击星标只切换收藏、不触发行的跳转。下面可直接体验（悬停行、点星星）：

③ 物品 Tooltip 标记

已收藏的物品，在任何地方（游戏自带 tooltip、聊天链接、掉落列表）悬停时，底部追加一行金色标记。必须挂在现有 tooltip 管线的单次通道守卫之后——这条管线不可重入，是我们踩过实锤的地方。

[破坏者之刃]
单手剑
伤害 42 - 64 · 速度 2.70
需要等级 42
⭐ 已在心愿清单
-- 追加行伪代码（挂 TooltipDataProcessor 后置钩子）
if WishList.IsMarked(itemID) then
    tip:AddLine("⭐ 已在心愿清单", gold)
end  -- __tipBusy 守卫内，只跑一次

tooltip 钩子内绝不创建/移动帧，只 AddLine。

④ 心愿清单页（新页签）

主框架新增「心愿单」页签（与副本列表 / 专业页并列，仅无限服可加专业页并列逻辑）。左右分栏：左主区按来源分组陈列收藏的装备；右侧栏是「去哪打」计划——把心愿折算成要跑的副本和要杀的 boss，按件数从多到少排。

🗑 清空心愿单

分组顺序 = 副本（按副本列表卡墙的顺序）→ 开放世界 → 任务/制造/其他；组内按 boss 序排。每条目右侧显示该物品在此来源的掉率，与掉落页同口径。

⑤ 数据结构与事件流

-- SavedVariables: DungeonsForeverDB 里加一张表（只存 ID，名字/图标运行期向客户端要——既有口径）
DB.wishlist = {
  [16983] = { t = 1760000000, inst = "rfk", boss = 3 },  -- 收藏时间戳 + 首个已知来源（用于分组兜底）
  ...
}

-- 内部事件（仿现有消息总线）
DF_WISHLIST_CHANGED  -- 收藏/取消/清空时广播 → 掉落页星星、心愿单页、tooltip 同步刷新

-- 分组逻辑：复用 Data_DungeonLoot 已有的「掉落来源」表反查 itemID → (副本, boss 序)
-- 无副本来源 → 查世界掉落表 → 都没有归「其他」

⑦ 已知坑位预防（写进方案，动工前对照）

  • tooltip 管线不可重入——追加行必须走现有守卫通道，钩子内禁止动帧，防栈爆。
  • Titan 同层绘制顺序随机——星标若带边框纹理，边框上 OVERLAY 层、填充上 BORDER 层。
  • 数据只存 ID——不落物品名/图标（口径：界面名字唯一真源是客户端）。
  • 来源反查只用静态表——掉落来源反查走 Data_DungeonLoot / Data_AreaMap 同类静态表，不查运行时接口。
  • 三语链——新 UI 文案必须补进繁/英生成脚本的扫描名单，漏扫 = 对应语言静默缺键。
  • 行尾纪律——DungeonUI.lua 改后二进制复核行尾，防 AI 编辑工具改掉整文件行尾。
  • 零孤儿媒体——星标优先用现有 HUI 字形/纹理，新增贴图须有引用并同步登记。
