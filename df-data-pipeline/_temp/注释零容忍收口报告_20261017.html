一、为什么还有注释（上一轮的漏网）

上一轮只清了 Core/*.lua 顶层 + 3 个 Data 文件，Core/Data/ 子目录整个没进清单。所以清完后仍剩 148 个文件 / 993 行注释 —— 其中 970 行是文件头注释块（几乎全是 26 个生成器各自写出的同一套 banner 模板）。

最夸张的一处：Core/Data/Data_VendorPrices.lua 单文件 642 处注释（行尾 638 处，几乎每行都挂着一条说明）。

二、本轮执行的三件事

① 现存 lua：全部清零

新工具 _temp/strip_lua_comments.py：真词法扫描（strip_comments.comment_spans，字符串里的 -- 不会误伤）、默认范围 Core + Locales、行尾风格原样保留、落盘前做「代码投影」硬校验（剥掉注释与空白后的字符流必须逐字节一致，不一致即拒绝写盘）。

  • Core / Locales：整行 997 + 行尾 703 处
  • 自家 Libs/LibHUI：47 + 6 处（--include-libhui）
  • 豁免：Libs/ 下 5 个第三方库（CallbackHandler / LibDBIcon / LibDataBroker / LibStub / UTF8）—— 那里的注释是版权与许可声明，删掉等于抹对方的署名

备份：_temp/_cmt_bak_full_20261017/（150 文件 / 14 MB，扩展名已改 .lua.bak）。

② 生成器：改了模板，重跑不会把注释带回来

注释的源头在 26 个生成器脚本的模板常量里（HEAD / HEADER / head / append('-- …') 等）。只删产物不改模板 = 下次重跑数据立刻回潮。

新工具 _temp/gen_tpl_strip.py：用 AST 定位「会写进 lua 的字符串常量」，再用 lua 词法只剥注释行 —— 模板里的代码行（local _, ns = ... / locale 守卫 / ns.X = {）原样保留；含 %s 格式化占位的模板自动跳过（清空会让 '' % x 抛 TypeError）。

踩到的坑（已修，值得记）：AST 的 col_offset / end_col_offset 是行内 UTF-8 字节偏移，第一版工具按字符算偏移，在含多字节中文的模板上越界吃掉了引号 —— 18 个文件一度全是坏的。已改成按字节切，并加 ast.literal_eval(切片) == 节点值 硬校验（不符即跳过不改）；随后从 .bak 全量回滚重跑。证据脚本 _temp/_tpl_verify.py。

③ 门禁：让回潮不再静默

上一轮的最大教训是门禁假绿：打包前检只查「注释里有没有别的插件名」，完全不管注释的数量与内容。现新增 _temp/check_zero_comments.py，口径 = 打包集里出现任何一行 lua 注释即 FAIL（Libs/ 第三方豁免），已接进两处：

  • _temp/pack_verify.py —— 打包前检
  • _temp/run_all_checks.py —— 日常全量回归（第 6 项）

双向验证过：0 行时输出 [OK] 注释零容忍，人为追加一行注释立刻 [FAIL]。
