五人本页 · 「卡中卡」提亮方案

规则：卡片套卡片时，内卡必须比外层卡亮一档 · 审计范围 = 五人本详情页（掉落 / 任务 / 攻略 / 地图）
嵌套判定规则：外层是可见容器卡（有底色的 plate / 卡），里面的行若也是「卡」（有底色），就必须提亮一档； 页面直铺的一层卡（下面直接是窗口底）不算嵌套，维持 L1；卡内扁平无底行（flat 定式）不是卡，不算嵌套。

③ 改动范围与实现方式

推荐

方案 A · 内卡提亮（最小改）

只动两处违规点：任务行、NPC 节点行。

  • 任务行 / NPC 节点行：L1 → L2 底 + 白 10% 边
  • 两者悬停胶囊：L3 → L4（保持 +2 档惯例）
  • 任务行「选中」= 胶囊常显，同步升 L4
  • 实现：HuiCardFX 加一个底色档位参数，其他调用方不传=默认 L1，零波及
  • 外底板、掉落页、攻略卡、地图卡：一律不动

方案 B · 级联全亮（不推荐）

把主窗口也算「外卡」：页面直铺的卡全部 L1 → L2，内卡 → L3。

  • 波及卡墙、掉落列表、攻略四卡、地图分组卡等已验收页面
  • 整体观感上移，窗口底与卡的对比反而变小
  • 检查断言与变异锚点需大面积重锚
改动清单（方案 A）：Core/DungeonUI.lua 两处（任务行 takeRow、NPC 节点行 takeNode 的 HuiCardFX 调用）＋ Hui.lua 助手加档位参数； 同步升级 df_dungeon_check 对应断言 + df_mut_check 重锚（预计 4–6 条）。改动完成后照例跑五项检查。
